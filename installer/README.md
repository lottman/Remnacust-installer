# Установщик Remnacust — справочник

[Русский](README.md) · [English](README.en.md)

**Установщик 1.2.152**: панель/страница 1.1.7.106, Node 1.1.27, Core 1.1.17 на стабильном Xray v26.11.9. Установщик поддерживает Ubuntu 22.04/24.04/26.04 LTS и Debian 12/13, Linux amd64/arm64. При установке Docker используется официальный репозиторий своей ОС. Для нового учёта автовыбора обновите ноды и подписки клиентов; исторический расход не перераспределяется. Версии, быстрый запуск и пути: [основной README](../README.md).

## Установка готового комплекта

Скачать последний стабильный установщик и открыть его интерактивное меню:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/lottman/Remnacust-installer/main/Install.sh) @ install
```

## Основной домен подписки и .env

Настройка находится в **Подписка → Настройки → Страницы подписки → Домены подписок**. Основной домен синхронизируется с `SUB_PUBLIC_DOMAIN` файла `/opt/remnacust/panel/.env` через локальную службу установщика. На старой установке сначала выполните обновление новым скриптом, чтобы служба и её bind mount были установлены.

Изменение через UI сохраняет согласованные настройки; ручная правка `.env` подхватывается при запуске, обновлении списка и периодической сверке. При ошибке связи интерфейс показывает ошибку синхронизации, а не успех. Секреты и реквизиты БД не меняются вместе с доменом.

CDN хранится в реестре панели и привязывается к основному домену: максимум три CDN на основной. Это не три разных подписки пользователя. У доменов есть стабильные UUID; отдельные API-права позволяют читать все, обычные или CDN-ссылки пользователя. Копируйте из UI текущие источник, Host/SNI и сгенерированную пару заголовка запроса. Существующую ссылку без ID CDN при необходимости замените выданной панелью, чтобы распознавание не зависело от переписанного Host.

Внешний CDN, DNS и неизвестные конфигурации Nginx/Caddy не редактируются произвольно. Отключите принудительный общий кеш ответов подписки в кабинете провайдера. Публичный домен подписки и внутренний `REMNAWAVE_PANEL_URL` страницы — разные параметры.

## Системные пакеты и вопросы при обновлении

Перед выбранной командой CLI выполняются `apt-get update -y` и `apt-get upgrade -y --with-new-pkgs`, кроме проверки выпуска `--check-release` и фонового обновления панели, запущенного её службой. Подтверждение продолжения APT автоматическое, независимо от `--yes`. Обновление индекса должно завершиться без ошибок источников. Обновление пакетов разрешает новые зависимости, но не удаляет пакеты и не снимает hold. Меню, справка, выход и `--dry-run` не изменяют системные пакеты; вложенные шаги одного действия не повторяют upgrade.

В SSH обычное подтверждение APT принимает `-y`. Вопросы настройки dpkg/debconf, выбора консоли и перезапуска служб остаются в текстовом интерактивном вводе. `--yes` не выбирает эти настройки; ответы не записываются в журнал установщика. Ошибка APT или отказ останавливают действие. Блокировки dpkg ожидаются до 120 секунд, файлы блокировок принудительно не удаляются.

Фоновое обновление из панели обновляет компоненты приложения; обслуживание ОС откладывается до отдельного SSH-сеанса и отмечается в журнале. Наличие новых пакетов ядра не блокирует эту операцию. Для остальных команд без терминала сохраняется проверка плана и код `75`, если требуются изменения пакетов; ответы по умолчанию не подставляются. Автоматической перезагрузки сервера нет, но обновляемые пакеты могут перезапускать службы. Новый пакет ядра начинает использоваться после отдельной перезагрузки; наличие исправления CVE проверяйте по бюллетеню дистрибутива.

В уже установленном комплекте 1.2.137 старый агент вызывает старый CLI до загрузки нового выпуска. Для получения этого исправления сначала один раз обновите установщик и службу обновления новым проверенным скриптом через SSH. Изменение исходников или публикация нового выпуска сами по себе не заменяют уже работающий старый агент.

## Подробная диагностика

CLI сохраняет один `logs/installer-<компонент>.log` до следующего действия с тем же компонентом. Диагностика использует отдельный файл. При сбое, включая прерывание, выводится путь и команда просмотра. Для SSH-обслуживания ноды дополнительно сохраняется `logs/node-maintenance.log` на ноде.

## Обновление из панели

При установке/обновлении создаётся `remnacust-panel-update.service`. Нужен systemd; без него используйте CLI. Администратор запускает обновление из окна версии; сервис продолжает работу после остановки backend и закрытия вкладки.

Проверяются соответствующий опубликованный комплект, архитектура, резервная копия и готовность приложений. Повторный запрос не должен создавать вторую операцию. Браузер видит этапы, журнал и итог. Диагностика автономности нод не блокирует обновление только из-за отсутствия подтверждения; предупреждение сохраняется. `--allow-disruption` явно пропускает эту диагностику, но не обещает отсутствие перерыва.

Приложения получают read-only каталог `/run/remnacust-control`; Docker socket в контейнер панели не передаётся. Unix socket защищён правами и ключом, производным от `APP_SECRET`. API-токен не заменяет право администратора. Приватный журнал находится в `/opt/remnacust/logs/panel-update-<id>.log`.

## Установка

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/lottman/Remnacust-installer/main/Install.sh) @ install-panel
bash <(curl -fsSL https://raw.githubusercontent.com/lottman/Remnacust-installer/main/Install.sh) @ install-node
bash <(curl -fsSL https://raw.githubusercontent.com/lottman/Remnacust-installer/main/Install.sh) @ install-subscription-page
```

Команда скачивает последний стабильный установщик. В вопросе о версии нажмите Enter для Latest; `--version` нужен только для выбора конкретного выпуска.

Обязательные пустые поля запрашиваются повторно; y/n следует своему показанному default. Домен подтверждается отдельно с default `y`. При автоматизации используйте `--yes` вместе со всеми необходимыми параметрами и явным выбором `--subscription-page` / `--no-subscription-page`.

| Параметр | Назначение |
| --- | --- |
| `--version latest\|1.2.152` | Выпуск комплекта установщика. |
| `--domain DOMAIN` | Домен компонента без протокола, порта и пути. |
| `--port PORT` | Loopback-порт панели или API-порт ноды. |
| `--directory PATH`, `--container NAME`, `--compose-file PATH` | Явное определение существующей установки. |
| `--project-name NAME` | Отдельное имя проекта Compose. |
| `--proxy caddy\|existing` | Новый управляемый Caddy либо существующий proxy. |
| `--tls-method auto\|http\|cloudflare\|gcore\|existing` | Метод TLS в поддерживаемом для компонента сценарии. |
| `--email EMAIL` | Почта регистрации ACME. |
| `--cert-file PATH`, `--key-file PATH` | Готовый сертификат и ключ. |
| `--dns-credentials PATH` | Закрытый INI выбранного DNS-провайдера. |
| `--server-ip IP[,IP]` | Публичные адреса для проверки DNS, в том числе за NAT. |
| `--node-domain DOMAIN` | Управляемый HTTPS/XHTTP endpoint ноды. |
| `--panel-ip IP[/CIDR]` | Ограничение всех входящих портов и ICMP адресом панели, кроме SSH. Включает VPN/CDN-порты; не подходит для прямого доступа остальных клиентов к ноде. |
| `--net-admin`, `--no-net-admin` | Выбор capability контейнера; включённое право сохраняется при обновлении. |
| `--subscription-page`, `--no-subscription-page` | Установка/перенос сайта подписки либо отказ. |
| `--subscription-urls URLS` | Один или два адреса сайта через запятую; это не каталог CDN панели. |
| `--subscription-port PORT` | Loopback-порт сайта, по умолчанию 3010. |

Скрипт устанавливает Docker только при отсутствии. Для панели создаются случайные секреты и отдельный пароль резервных копий; его копия находится в приватном `backup-password.txt`. Существующие `APP_SECRET`, `SECRET_KEY`, пароли БД, сети и тома не заменяйте вручную.

## Управление установленными компонентами

```bash
sudo remnacust manage-panel
sudo remnacust manage-node
sudo remnacust manage-subscription-page
sudo remnacust show-config --component panel
sudo remnacust status --component node
sudo remnacust logs --component subscription-page --page-id ID
sudo remnacust restart --component node
```

Рабочие каталоги постоянные. `show-config` показывает адреса и пути без вывода секретов. Состояние страницы определяется по зарегистрированному экземпляру и Docker, а не только по наличию адреса в `.env` панели.

### Подключение страницы подписки к панели

Локальная панель выбирается как `auto`; удалённая — по HTTPS URL без dashboard-пути, query и пароля в URL. Скрипт проверяет metadata, список/выбранную конфигурацию страницы и права токена до применения изменений.

```bash
sudo remnacust install-subscription-page --panel-url https://panel.example.com --panel-token-file /root/subscription-token
sudo remnacust configure-subscription-page --page-id ID --panel-url https://other-panel.example.com --panel-token-file /root/subscription-token
```

Токен вводится скрыто, через `REMNACUST_SUBSCRIPTION_TOKEN` или обычный файл `0600`. Минимальные права: `system:metadata`, `subscriptions:subpage-config`, `subscription-page-configs:get`, `subscription-page-configs:list`. Токен с правами на всех пользователей сайту не нужен. Сертификаты проверяются; redirect с серверным токеном не используется как обход неверного адреса.

Для смены данных выберите соответствующее действие в меню `manage-subscription-page` либо `configure-subscription-page`. Меняется только выбранный сайт, образ/домен/proxy/БД сохраняются. Ошибка проверки не меняет настройки; ошибка готовности после применения возвращает прежнюю конфигурацию. Остановленный сайт остаётся остановленным.

Дополнительные страницы имеют отдельные `--project-name`, `--domain`, порт и при необходимости `--directory`; без явно выбранного каталога используются `/opt/remnacust/subscription-pages/<project>`. Реестр: `/opt/remnacust/registry/subscription-pages`.

### Сайт на ноде

Нода с собственным доменом получает один из 20 случайных сайтов с локальными страницами и ресурсами. Выбор сохраняется при обновлении; авторские файлы не заменяются. Рабочий каталог — `www/` внутри каталога ноды.

Для другого варианта: `sudo remnacust configure-node-site`. После подтверждения прежние файлы сохраняются в `backups/node-sites/`. Работающий Nginx пересоздаётся и проверяется; при ошибке выполняется попытка отката. Xray не перезапускается. [Подробная настройка selfsteal](../docs/NODE-SELFSTEAL.md).

### Смена домена и TLS

```bash
sudo remnacust change-domain --component panel --domain panel.example.com
sudo remnacust change-domain --component node --domain node.example.com --email admin@example.com
sudo remnacust change-domain --component subscription-page --page-id ID --domain sub.example.com
```

Это смена домена, а не перенос на другой IP. Заранее настройте A/AAAA. Для Caddy и HTTP-01 проверяется соответствие серверу; для готового сертификата нужна подходящая пара ключ/сертификат. Способ TLS сохраняется. Перед Certbot защищённая операция UFW сохраняет исходное состояние и восстанавливает его после завершения/ошибки; HTTP-01 ограниченного node-firewall временно открывает TCP 80 на время проверки.

Скрипт изменяет только распознанную управляемую конфигурацию. Незнакомый внешний proxy/CDN не переписывается. Сохраняются ключи, реквизиты БД, тома и API-порты; остановленные сервисы не запускаются произвольно. При ошибке предусмотрен откат конфигурации и состояния. Закрытые копии находятся в `/opt/remnacust/backups/domain-*`.

Адреса/SNI хостов и уже импортированные подписки проверяйте отдельно. Смена публичного домена панели не должна подменять независимый домен сайта подписки.

## Миграция и обновление

```bash
sudo remnacust upgrade-panel
sudo remnacust upgrade-node
sudo remnacust upgrade-subscription-page --page-id ID
bash <(curl -fsSL https://raw.githubusercontent.com/lottman/Remnacust-installer/main/Install.sh) @ migrate-remnawave-panel --container remnawave
bash <(curl -fsSL https://raw.githubusercontent.com/lottman/Remnacust-installer/main/Install.sh) @ migrate-remnawave-node --container remnanode
```

При обновлении сохраняются конфигурация, mounts и секреты. Панель получает согласованную копию PostgreSQL до остановки приложений. Обновление агента и бинарника Xray может прервать клиентские соединения; обновление одной панели не обновляет удалённый Core.

Файлы с датами архивируются в `backups`, а не размножаются в рабочем каталоге. Для старого layout есть `normalize-layout`; для распознанных копий рядом с конфигами — `cleanup-backups`. При нестандартных внешних каталогах и разных файловых системах автоматический перенос ограничен проверками безопасности.

## Обнаружение старых страниц Remnawave

При обновлении/миграции скрипт обнаруживает прежние страницы и отдельно спрашивает, переносить ли их на Remnacust. Можно сохранить текущую панель или выбрать другую. Сохраняются домены, порт, prefix и настройки подключения. Наш образ Remnacust повторно не предлагается как старая сторонняя страница. Название Compose-проекта само по себе не доказывает используемый образ.

## Восстановление данных

`restore-panel --backup PATH` сохраняет установленную версию приложения и возвращает БД вместе с соответствующим `APP_SECRET`. Старые версии PostgreSQL/Valkey и Compose из архива автоматически не запускаются. Для встроенного сайта восстанавливается согласованный токен, для службы обновления — соответствующий производный ключ. Остановленные приложения остаются остановленными.

Копии содержат секреты. Сохраняйте архив, пароль, окружение и постоянное состояние нод отдельно от сервера. При сбое миграции не подменяйте ключ восстановленной БД случайным новым. Внутренние протоколы квот/recovery могут требовать отдельного порядка восстановления; их незавершённые режимы не объявляются готовыми одной этой командой.

## Удаление

```bash
sudo remnacust uninstall-panel
sudo remnacust uninstall-node
sudo remnacust uninstall-subscription-page --page-id ID
```

Подтверждение удаления по умолчанию — `n`. Сохраняются настройки, сертификаты, тома и резервные копии. У страницы удаляются только выбранные контейнеры и принадлежащий ей отдельный proxy; общий proxy и панель сохраняются. Повторная установка архивирует прежнюю конфигурацию в `backups/reinstalled-subscription-page-*/configuration`.

## Проверки и публикация

`Source checks` проверяет скрипт, Docker-сценарии, права, proxy и пакетирование на отдельных тестовых ресурсах. `Publish Docker release` запускается вручную по тегу; проверяет версии/архитектуры, шесть образов и совместную работу панели со страницей, затем создаёт черновик с контрольными суммами. После проверки публичного скачивания выпуск публикуется отдельно.

Изменение README не требует новых версий, перепаковки helper-bundle или изменения закреплённых коммитов компонентов. [Порядок выпуска](../docs/PUBLISHING.md) · [Лицензии](../NOTICE.md).

## MPTCP и ядро Linux

Xray v26.11.9 выключает MPTCP по умолчанию и сохраняет явный `streamSettings.sockopt.tcpMptcp`. Новые отдельные Caddy-службы панели и страницы подписки получают `GODEBUG=multipathtcp=0`. Существующий общий proxy при обновлении приложения не перенастраивается и не перезапускается. Для других Go-служб проверьте эту настройку отдельно.

CVE-2026-98432 исправляется обновлением ядра хоста и загрузкой исправленного ядра; обновление Docker-образа этого не делает. Проверяйте статус конкретного пакета по бюллетеню дистрибутива. До подтверждения исправления MPTCP должен оставаться выключенным. После исправления его можно включить явно. Проверка слушателей: `sudo ss -Mlnp`; `uname -r` показывает запущенное ядро, но сам по себе не доказывает наличие исправления. [Xray](https://github.com/XTLS/Xray-core/releases/tag/v26.11.9) · [Go Security Team](https://groups.google.com/g/golang-announce/c/PCoQcdxoScw/m/aD-MgXEvAAAJ).


Перенос ноды использует существующий ключ, API-порт и состояние Xray. Мастер предлагает TLS/XHTTP и сайт, способ получения сертификата и необязательные настройки firewall. Уже настроенный TLS можно сохранить. Дополнительный TLS настраивается после переноса; его сбой не удаляет перенесённую ноду. Работающий профиль Xray сохраняется: соответствующий inbound задайте в панели, как при новой установке.

NeedRestart показывает ожидающие перезапуска службы, но не перезапускает их и сервер автоматически. Вопросы настройки dpkg остаются интерактивными.

### Перенос установленной страницы Remnawave

На сервере со страницей выберите **Перенос → Страница подписки из Remnawave** либо выполните `sudo remnacust migrate-remnawave-subscription-page`. Для точного выбора доступны `--container ИМЯ` или `--directory /opt/subscription-page`. Сохраняются адрес панели, API-токен, порты, сети, подключённые файлы и состояние запуска. Панель не обновляется, остальные сервисы проекта не перезапускаются. Если проверка готовности не прошла, восстанавливается прежняя конфигурация страницы. Неизвестные кастомные образы и контейнеры без исходных Compose-файлов требуют ручного переноса. После переноса используйте `upgrade-subscription-page`, а для смены подключения — `configure-subscription-page`.
