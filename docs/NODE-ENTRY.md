# Постоянный вход и ограничение ноды

`configure-entry-node --entry-config FILE` создаёт отдельный TCP-вход на HAProxy. JSON содержит `listenPort`, `strategy` (`priority`, `roundRobin`, `leastConnections`) и `backends` со списком IP/портов. Панель формирует его из нод **одного хоста**, проверяет общий inbound и применённые порты и передаёт через существующий SSH-канал. Новый конфиг сначала проходит `haproxy -c`, затем сервис `remnacust-entry` запускается или плавно перезагружается. При ошибке возвращается предыдущая конфигурация. Другой HAProxy и Xray не перезапускаются.

Домен и порт хоста должны постоянно вести на входной сервер. Конечные ноды должны иметь одинаковые ключи, inbound и подходящий сертификат. TCP-проверки выполняются каждые 2 секунды, с двумя неудачами или успехами для смены состояния. Приоритет использует первый доступный сервер. Новые соединения выбирают конечный сервер на входе; изменения состава применяются повторно через SSH и не требуют обновления клиентской подписки. Открытые соединения не мигрируют и при плавной перезагрузке сохраняются до завершения или предельного часа. UDP-транспорты не поддерживаются. TCP-проверка не подтверждает авторизацию VPN. TLS завершается на конечной ноде, входу сертификат не нужен. Конечная нода видит исходный IP входного сервера.

```json
{"listenPort":443,"strategy":"priority","backends":[{"address":"192.0.2.11","port":8443},{"address":"192.0.2.12","port":8443}]}
```

```sh
bash installer.sh configure-entry-node --entry-config entry.json --yes
```

Для новой ноды `--panel-ip IP[/CIDR]` ограничивает **все входящие порты и ping** адресом главного сервера. Исключение — SSH: 22, текущий порт SSH и порты из `sshd -T`. Клиенты VPN должны идти через главный сервер. Правила учитывают Docker forwarding и IPv6 и не очищают чужие таблицы. Действующие ограничения провайдера/UFW продолжают действовать. Политика восстанавливается сервисом `remnacust-node-firewall`; удаление контейнера её не удаляет.

Исходящие ответы и трафик от обнаруженных Docker-мостов сохраняются. После ручного добавления новых Docker-мостов выполните `python3 /etc/remnacust-node-firewall/guard.py restore`. Для ноды за этой защитой используйте DNS-01 или внешнее управление сертификатами: HTTP-01 из интернета будет закрыт. Главный IP должен совпадать с реальным адресом выхода TCP-входа.

Удалить только эту политику:

```sh
python3 /etc/remnacust-node-firewall/guard.py remove
```

Настройки хранятся в `/etc/remnacust-node-firewall`, отдельная таблица — `inet remnacust_node_guard`. Команда не меняет чужие правила. Если другой firewall закрывает SSH, эта политика не откроет его.

Пакетные проверки выполняются только в изолированных сетевых пространствах Linux:

```sh
sudo python3 tests/test_node_firewall.py --network
sudo python3 tests/test_stable_entry.py --network
```
