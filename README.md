# Remnacust Installer

Установка, обновление, перенос и обслуживание панели, ноды и сайта подписки. На сервер скачиваются готовые Docker-образы; компиляция Node.js/Go на VPS не требуется.

## Сначала: где находятся файлы

| Компонент | Рабочие файлы |
| --- | --- |
| Панель | `/opt/remnacust/panel/.env`, `/opt/remnacust/panel/docker-compose.yml` |
| Нода | `/opt/remnacust/node/.env`, `/opt/remnacust/node/docker-compose.yml` |
| Основная страница подписки | `/opt/remnacust/subscription-page/.env`, `/opt/remnacust/subscription-page/docker-compose.yml` |

Активные пути: `cat /opt/remnacust/FILES.txt`. Для дополнительных страниц используются отдельные постоянные каталоги и ID. Явно выбранная внешняя директория может отличаться.

```bash
cd /opt/remnacust/panel
ls -la
nano .env
docker compose config --quiet
docker compose up -d --no-build --pull never
```

`restart` не перечитывает `.env`. Не создавайте новый пустой `.env` в `/opt/remnacust` и не заменяйте исходные ключи/пароли БД. `backups/` содержит копии, `logs/` — журналы, `registry/` — реестр установок, `control/` — службу управления. Это не дополнительные рабочие копии приложения.

Старую структуру своих установок можно привести к постоянным путям через `remnacust normalize-layout --component panel|node`. Старые неиспользуемые каталоги архивируются в `backups/retired-layout`. Команда `remnacust cleanup-backups` переносит распознанные копии конфигурации в каталог резервирования; не воспринимайте её как удаление всех копий БД.

## Обновление системных пакетов перед действиями

Каждая выбранная команда CLI сначала выполняет `apt-get update`, затем `apt-get upgrade --with-new-pkgs` — эквивалент обновления через `apt update` и `apt upgrade`, включая новые зависимости установленных пакетов ядра. Это относится также к состоянию, журналам, резервным копиям, удалению и проверке выпуска. Перед открытием меню, справкой и выходом пакеты не обновляются; `--dry-run` не меняет систему. Внутренние шаги одного действия не повторяют общий upgrade.

APT и dpkg работают в переднем плане SSH-терминала. На выбор кодировки, раскладки, сохранения конфигурации и перезапуска служб отвечает оператор. `--yes` подтверждает действие Remnacust и не выбирает ответы пакетов. Ответы не копируются в журнал установщика. Ошибка или отказ останавливают действие; блокировки dpkg ожидаются до 120 секунд, файлы блокировок не удаляются.

Без терминала сначала проверяется план пакетов. Если нужны установка, обновление или настройка пакетов, операция останавливается с указанием повторить команду через SSH. Это относится и к обновлению из панели: сначала обновите пакеты интерактивно, затем повторите действие. На уже обновлённой системе запуск без терминала продолжается. Автоматической перезагрузки сервера нет; необходимость перезагрузки показывается отдельно. Обновление пакетов может перезапускать службы и прерывать соединения.

## Быстрый запуск

Поддерживаются Ubuntu 22.04/24.04/26.04 LTS, Linux amd64/arm64. Нужны root, доступ к пакетным репозиториям и скачиванию образов. Для панели: от 2 CPU, 2 GiB RAM, 20 GiB диска; рекомендуются 4 CPU и 4 GiB RAM. Для ноды: от 1 CPU и 1 GiB RAM с запасом под нагрузку.

```bash
curl -fsSL --proto '=https' --proto-redir '=https' https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh -o installer.sh
sudo bash installer.sh
```

Либо выберите действие сразу:

```bash
sudo bash installer.sh install-panel --version 1.2.123
sudo bash installer.sh install-node --version 1.2.123
sudo bash installer.sh install-subscription-page --version 1.2.123
```

Образы опубликованы для amd64/arm64; скачивание релиза и GHCR открыто без персонального токена. Установщик проверяет выпуск, архитектуру и целостность. Docker добавляется при отсутствии; существующий daemon не переустанавливается ради обновления приложения.

| Состояние / логи | `status`, `logs` с `--component panel|node|subscription-page` |

После установки команды доступны через `sudo remnacust COMMAND`. Номера интерактивного меню — подсказки интерфейса; для автоматизации используйте названия команд.

## Новая установка

Обязательные поля повторно запрашиваются при пустом вводе. После домена показывается подтверждение с ответом по умолчанию `y`; остальные подтверждения используют указанный в вопросе default. Перед действиями проверяются установленный компонент, DNS, порты и выбранная схема HTTPS.

Панель спрашивает, устанавливать ли сайт подписки. Для автоматизации задавайте выбор явно:

```bash
sudo bash installer.sh install-panel --domain panel.example.com --email admin@example.com \
  --subscription-page --subscription-urls sub.example.com --yes
```

`--no-subscription-page` оставляет только панель. Без интерактивного терминала `--yes` не должен подменять явный выбор сайта. Для уже существующего сайта можно указать `--no-subscription-page --subscription-urls https://sub.example.com`.

Панель получает случайные секреты и пароль БД. Пароль резервных копий задаётся отдельно; Enter создаёт его автоматически. Сохраните показанный пароль и приватный `backup-password.txt` вне сервера. После запуска создайте администратора в панели.

### Адреса сайта подписки

`--subscription-urls` принимает один или два адреса сайта через запятую; первый используется как основной. При установке нового сайта его домен отличается от домена панели. Для уже работающего сайта используйте `--no-subscription-page --subscription-urls https://sub.example.com`, чтобы сохранить адрес без создания второго контейнера. Дополнительные CDN настраиваются в каталоге доменов панели и в кабинете провайдера.

### Сертификат и почта

Новая панель поддерживает Caddy HTTPS, Cloudflare/Gcore DNS и готовый сертификат. При существующем proxy используйте `--proxy existing`. Проверка A/AAAA учитывает `--server-ip` для NAT. Публичная DNS-запись должна соответствовать серверу; внутренние API, БД и кеш не становятся публичными сервисами.

### TLS и XHTTP

Для ноды доступны управляемый Nginx, HTTP-01, DNS-проверка и готовая пара сертификат/ключ. `--net-admin` — capability контейнера для сетевых операций, а не установка отдельного пакета. Уже включённое право сохраняется при обновлении.

`--panel-ip` разрешает входящие порты и ping только от панели, кроме SSH. Прямые клиенты/CDN с других адресов тогда не попадут на inbound. HTTP-01 временно открывает TCP 80 для получения/продления сертификата и возвращает ограничения после операции.

## Страницы подписки отдельно

```bash
sudo remnacust install-subscription-page --panel-url https://panel.example.com
sudo remnacust manage-subscription-page
sudo remnacust upgrade-subscription-page --page-id ID
sudo remnacust configure-subscription-page --page-id ID --panel-url https://other-panel.example.com
sudo remnacust uninstall-subscription-page --page-id ID
```

Наличие панели или адреса подписки в `.env` не доказывает установку сайта. В списке страниц показываются зарегистрированные экземпляры, домены, ID и фактическое состояние контейнеров. Основная страница использует loopback 3010; дополнительные экземпляры — свободный порт и собственный проект/каталог. Чужой процесс на занятом порту не завершается.

Сайт может использовать локальную панель или удалённую по HTTPS. Токен вводится скрыто, через `REMNACUST_SUBSCRIPTION_TOKEN` или файл `--panel-token-file` с правами `0600`. Не передавайте секрет в аргументе командной строки. Нужны только права страницы: `system:metadata`, `subscriptions:subpage-config`, `subscription-page-configs:get`, `subscription-page-configs:list`.

В панели локальные сайты управляются в **Подписка → Настройки → Страницы подписки**. Доступны запуск, остановка, перезапуск и обновление зарегистрированной страницы. Установщик сохраняет остановленное состояние; произвольные пути, образы и Docker-команды из браузера не принимаются.

## Перенос установленной страницы подписки

При обновлении/переносе панели найденный прежний сайт предлагается отдельно: переносить его или оставить. Наш образ Remnacust повторно не предлагается как старый Remnawave. Можно оставить прежний backend либо указать другую панель и токен. Сохраняются домен, порт, prefix и настройки; доступ к выбранному API проверяется до изменения окружения.

## Где находятся настройки

Основной домен: **Подписка → Настройки → Страницы подписки → Домены подписок**. Он синхронизируется с `SUB_PUBLIC_DOMAIN` в `.env` через локальную службу установщика. На основной домен — до трёх CDN; карточка пользователя и API выдают обычные и CDN-ссылки отдельно.

Для VK/Yandex используйте сгенерированные в карточке CDN источник, Host/SNI и пару заголовка запроса. Настройка провайдера выполняется в его кабинете. Публичные ссылки и URL геофайлов сохраняют зарегистрированный CDN-адрес; серверный URL панели не является клиентской ссылкой. Принудительное кеширование ответов подписки отключается.

[Настройки и ограничения](installer/README.md#основной-домен-подписки-и-env) · [Геофайлы](https://github.com/lottman/Remnacust-panel/blob/main/docs/GEOFILES.md).

## Миграция и обновление

```bash
sudo remnacust upgrade-panel
sudo remnacust upgrade-node
sudo remnacust upgrade-subscription-page --page-id ID
sudo bash installer.sh migrate-remnawave-panel --container remnawave
sudo bash installer.sh migrate-remnawave-node --container remnanode
```

Установщик сохраняет Compose, окружение, секреты и постоянные данные. Нельзя заменять исходный `APP_SECRET`: он связан с зашифрованными настройками. Существующий внешний proxy не переустанавливается автоматически. Совместимость сохранённых политик ядра проверяется до запуска нового образа.

Обновление панели показывает этапы и журнал через локальную systemd-службу, которая продолжает работать после остановки backend. API-токен не даёт административного права на обновление. Диагностика автономности нод предупреждает о возможном перерыве и не требует обязательного `--allow-disruption` для обычного обновления. Самостоятельная замена ядра или рестарт контейнера ноды может прервать соединения.

## Перенос Marzban

Используйте `migrate-marzban-panel` с адресами источника/назначения и подходящими правами. Параметры выбора сквада, квоты и сохранения ссылки сверяйте с `--help` и [руководством переноса](https://github.com/lottman/Remnacust-panel/blob/main/docs/USER-MIGRATION.md). Это перенос данных пользователей через API, а не запуск старой БД как новой панели.

## Резервные копии и восстановление

```bash
sudo remnacust backup-panel
sudo remnacust restore-panel --backup /opt/remnacust/backups/panel-DATE-ID
```

Восстановление сохраняет установленную версию приложения, возвращает БД и связанный `APP_SECRET` из выбранной копии. Старые Compose, PostgreSQL и Valkey из архива автоматически не запускаются. Постоянное состояние нод и приватные журналы квот также требуют сохранения; это не замена только файла `.env`.

Встроенные ZIP-копии панели содержат зашифрованный сжатый PostgreSQL dump. Его не читают как обычный SQL-текст; нужен пароль архива и средства PostgreSQL. [Подробности копий](https://github.com/lottman/Remnacust-panel/blob/main/docs/BACKUPS.md).

## Удаление и повторная установка

Удаление подтверждается отдельно и сохраняет данные, конфигурацию, сертификаты и копии. Страница удаляется по своему ID; панель и её общий proxy не удаляются вместе с ней. Повторная установка архивирует прежнюю конфигурацию в `backups`, не создавая очередную рабочую папку с датой.

## MPTCP и ядро Linux

Xray v26.10.31 выключает MPTCP по умолчанию и сохраняет явный `streamSettings.sockopt.tcpMptcp`. Новые отдельные Caddy-службы панели и страницы подписки получают `GODEBUG=multipathtcp=0`. Существующий общий proxy при обновлении приложения не перенастраивается и не перезапускается. Для других Go-служб проверьте эту настройку отдельно.

CVE-2026-98432 исправляется обновлением ядра хоста и загрузкой исправленного ядра; обновление Docker-образа этого не делает. Проверяйте статус конкретного пакета по бюллетеню дистрибутива. До подтверждения исправления MPTCP должен оставаться выключенным. После исправления его можно включить явно. Проверка слушателей: `sudo ss -Mlnp`; `uname -r` показывает запущенное ядро, но сам по себе не доказывает наличие исправления. [Xray](https://github.com/XTLS/Xray-core/releases/tag/v26.10.31) · [Go Security Team](https://groups.google.com/g/golang-announce/c/PCoQcdxoScw/m/aD-MgXEvAAAJ).
