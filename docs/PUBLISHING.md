# Выпуск Remnacust

Исходники разделены между `Remnacust-panel`, `Remnacust-node`, `Remnacust-core` и `Remnacust-installer` в аккаунте lottman. Репозитории не удаляются при выпуске; новые изменения добавляются обычными коммитами.

1. Обновите версии компонентов, выполните проверки и создайте одинаковый тег, например `v1.1.1`, в панели, ноде и ядре. Архив ядра в ноде должен соответствовать исходникам выбранного ядра.
2. В `component-sources.json` установщика укажите полные хеши этих трёх коммитов. Обновите `VERSION`, инструкции и тесты установщика, затем создайте его тег.
3. Из checkout установщика выполните `python3 scripts/package-source-release.py --check v1.1.1`, затем команду без `--check`. Пакетировщик использует выбранный Git-тег и закреплённые коммиты, проверяет версии и запрещённые файлы. Случайные локальные `.env` не входят в архив.
4. Создайте черновик GitHub Release установщика и добавьте `release/installer.sh`, `release/remnacust-source-v1.1.1.tar.gz` и `release/SHA256SUMS`. Опубликуйте стабильный выпуск с отметкой Latest только после загрузки всех файлов. Workflow `Publish source release` выполняет те же действия при ручном запуске.
5. Проверьте `bash installer.sh --check-release --version 1.1.1`, затем новую установку и обновление на отдельном Linux-стенде. Для следующих исправлений выпуска используйте новый тег.

Пользователь скачивает публичные файлы без токена. Workflow загружает файлы стандартным временным `GITHUB_TOKEN` с правом `contents: write`. Docker-образы собираются на сервере пользователя, поэтому отдельный реестр не нужен.

Для локальной проверки пакетировщика без загрузки других репозиториев задайте `--local-sources /path/to/parent`, где находятся три соседних checkout с нужными коммитами. Полученный архив имеет тот же состав и контрольную сумму.
