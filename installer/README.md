# Remnacust Installer

Установка и обслуживание панели и ноды Remnacust. Нода включает наш Xray: отдельной команды обновления ядра нет. Образы собираются в GitHub Actions. Сервер скачивает готовый образ из GHCR по закреплённому digest; при недоступном реестре используется копия того же образа из публичного Release. Версия, архитектура и идентификатор проверяются до изменения установки. Сборки на VPS нет. Токен файлового хоста или GitHub не требуется.

## Быстрый запуск

Скопируйте всю строку в консоль сервера. Она скачает установщик и откроет меню:

```bash
curl -fsSL --proto '=https' --proto-redir '=https' https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh -o installer.sh && sudo bash installer.sh
```

[Скачать installer.sh](https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh). Для установки без меню добавьте в конец строки `install-panel` или `install-node`.

Для просмотра справки достаточно Bash: `bash installer.sh --help`. В меню установленный компонент получает действие «Удалить» вместо «Установить». Обновить отсутствующий компонент нельзя. Наличие установки проверяется по каталогу, Docker/Compose-файлу и записи установщика; остановленные контейнеры тоже считаются установленными. Цвета отключаются через `NO_COLOR=1`; журнал операции хранится в `/opt/remnacust/logs` с доступом только для root.

Если репозиторий скачан целиком, файл находится в `installer/installer.sh`.

## Команды

| Команда | Действие |
| --- | --- |
| `install-panel` | Новая панель, PostgreSQL 18, Valkey, Caddy с HTTPS |
| `install-node` | Новая нода с нашим Xray; Nginx и TLS — при `--node-domain` |
| `upgrade-panel` | Обновление API, worker и scheduler с копией БД |
| `upgrade-node` | Обновление ноды вместе с Xray |
| `uninstall-panel`, `uninstall-node` | Удаление контейнеров с сохранением данных, томов и конфигурации |
| `migrate-remnawave-panel` | Замена образов существующей панели с сохранением её Compose-проекта |
| `migrate-remnawave-node` | Замена образа существующей ноды с сохранением ключа и портов |
| `migrate-marzban-panel` | Перенос пользователей из Marzban в установленную Remnacust |
| `--check-release` | Скачать и проверить выпуск без установки |
| `status`, `logs` | Состояние контейнеров, последние 100 строк журнала |
| `start`, `stop`, `restart` | Управление приложением; остановка не удаляет БД и тома |
| `backup-panel`, `restore-panel` | Копия БД и конфигурации / восстановление выбранной копии |
| `renew-node-certificate` | Копирование обновлённого сертификата и перезапуск ноды/Nginx |

При установке, обновлении и миграции запрашивается версия выпуска установщика. Enter выбирает `latest`; `--version 1.1.6` закрепляет выпуск. Установщик 1.1.6 содержит панель версии 1.1.2, ноду и ядро 1.1.1: версии компонентов закреплены в `component-sources.json` и проверяются отдельно. `--yes` пропускает подтверждение, но обязательные параметры и ключи всё равно нужны.

```bash
sudo bash installer.sh install-panel --domain panel.example.com --version latest
sudo remnacust upgrade-panel --version 1.1.6
sudo remnacust status --component node
sudo remnacust backup-panel
sudo remnacust restore-panel --backup /opt/remnacust/backups/panel-DATE-ID
```

## Новая установка

Установка, обновление и миграция поддерживаются только на Ubuntu 22.04 LTS и Ubuntu 24.04 LTS, amd64 и arm64. На другой ОС установщик завершается до установки пакетов и изменения приложения. Проверка выпуска, справка и обслуживание ранее установленного приложения не ограничены этими двумя версиями ОС. При выборе старого выпуска установленная команда `remnacust` сохраняет проверку ОС текущего установщика.

Нужны root, доступ к GitHub, Docker Hub и репозиториям пакетов. Для работы панели нужны минимум 2 CPU, 2 GiB RAM и 20 GiB диска; рекомендуются 4 CPU и 4 GiB RAM. Для ноды — минимум 1 CPU и 1 GiB RAM, с запасом под нагрузку Xray. Node.js, npm и Go на VPS не нужны. Перед скачиванием проверяется запас диска для образа; исходники и инструменты сборки остаются в GitHub Actions. [Требования Remnawave](https://docs.rw/install/requirements/) используются для планирования ресурсов; список ОС установщика Remnacust ограничен двумя версиями Ubuntu.

Установщик добавляет Docker только при его отсутствии. Если установлен Docker без Compose v2, добавляется только пакет Compose. Существующий daemon не переустанавливается. SSH, системные sysctl и посторонние службы не перенастраиваются.

Панель получает случайные `APP_SECRET`, пароль PostgreSQL, пароль метрик и секрет webhook. HWID включён по умолчанию для новой установки. Backend публикуется только на `127.0.0.1`, БД и кеш не имеют публичных портов. Caddy обслуживает домен на 80/443; A/AAAA должны указывать на сервер, оба порта должны быть доступны. При `--proxy existing` HTTPS настраивается вашим reverse proxy. После запуска создайте администратора в панели.

Caddy работает в Docker, поэтому `systemctl status nginx` на новой установке панели возвращает «Unit could not be found». Проверяйте `sudo remnacust status --component panel` и `sudo remnacust logs --component panel`: там видны приложение и Caddy. При миграции установщик сохраняет прежний Caddy или Nginx, его образ, конфигурацию, сертификаты и порты; новый прокси не устанавливается.

Команды обслуживания и метаданные установки сохраняются до первого запуска. Если Caddy не получил сертификат из-за DNS или закрытого порта, исправьте причину, проверьте `sudo remnacust status` и `sudo remnacust logs`, затем выполните `sudo remnacust start`. Повторная установка поверх созданных файлов блокируется, чтобы сохранить секреты и данные.

Нода требует `SECRET_KEY` из этой панели — это пакет сертификатов для её авторизации, а не дополнительный токен скачивания. Ключ вводится скрыто. Для автоматизации передайте его через защищённое окружение `REMNACUST_NODE_SECRET`; не записывайте в историю команд. Формат, подпись, приватный ключ и срок сертификата проверяются до запуска.

```bash
sudo bash installer.sh install-node --port 2222 --panel-ip 203.0.113.10
sudo bash installer.sh install-node --port 2222 \
  --node-domain edge.example.com --email admin@example.com
```

`--panel-ip` добавляет правила доступа к API только в уже активный UFW. Установщик не включает и не сбрасывает firewall. Если UFW не активен, ограничьте порт API адресом панели в firewall провайдера. Укажите этот же порт при добавлении ноды в панели. Xray начнёт обслуживать пользователей после назначения профиля.

### TLS и XHTTP

`--node-domain` запрашивает сертификат Certbot через HTTP-01: DNS должен быть настроен, порт 80 — свободен. Сертификаты хранятся в `certs`, общий каталог сокетов — в `run`. Nginx принимает TLS с PROXY protocol на `/var/lib/remnacust/run/nginx.sock`; путь `/xhttppath/` направлен на `/var/lib/remnacust/run/xhttp.sock`. После продления сертификата deploy-hook копирует его и перезапускает Nginx и ноду.

Настройте в профиле Xray Unix inbound XHTTP: `listen` = `/var/lib/remnacust/run/xhttp.sock,0666`, `path` = `/xhttppath/`. Суффикс `0666` нужен для доступа worker Nginx к сокету. Для fallback на Nginx задайте `dest` = `/var/lib/remnacust/run/nginx.sock` и `xver: 1`. Сертификат и ключ доступны в `/var/lib/remnacust/tls/fullchain.pem` и `/var/lib/remnacust/tls/privkey.pem`. Публичный listener 443 принадлежит Xray. Профили панели автоматически не переписываются. Для REALITY без собственного TLS-сайта `--node-domain` не нужен.

## Миграция и обновление

```bash
sudo bash installer.sh migrate-remnawave-panel --container remnawave
sudo bash installer.sh migrate-remnawave-node --container remnanode
```

Можно указать `--directory /opt/remnawave` или `--compose-file /opt/remnawave/docker-compose.yml`. При нескольких установках используйте точное имя контейнера. Сохраняются имя Compose-проекта, сети, тома, образы БД/кеша, `.env`, порты и ключи. PostgreSQL 17 не заменяется на 18 во время миграции. Новая управляемая Compose-конфигурация создаётся рядом с исходной; исходные файлы остаются в резервной копии.

Требуется Compose v2 и исходный `APP_SECRET` панели либо `SECRET_KEY` ноды. Старую панель без `APP_SECRET` сначала обновите по официальному пути Remnawave. Отсутствующий секрет не заменяется случайным. Неизвестная, незавершённая или изменённая миграция БД останавливает перенос до выключения приложения. Установки с несколькими сетями приложения требуют предварительного выбора одной однозначной сети. Для внешней БД с дополнительными SSL-файлами заранее проверьте доступ резервного копирования; автоматический перенос нестандартных SSL-mounts не предусмотрен.

Готовый образ скачивается и проверяется до остановки приложения. Затем создаются копии БД и Compose; после остановки всех обнаруженных процессов делается окончательный dump. БД и кеш продолжают работать. Отдельные API/processor/scheduler обновляются вместе; ранее отключённые процессы не запускаются. Приложения вне этого Compose-проекта, подключённые к той же БД, нужно остановить отдельно.

Проверяются исходные учётные записи, ключи пользователей, профили и настройки. Старая сборка с переименованными таблицами и `xera1`-паролями исправляется встроенной процедурой совместимости, используя исходный `APP_SECRET`.

При неудаче обновления ноды запускается предыдущая конфигурация. Если панель уже начала менять БД, её процессы останавливаются и выводится команда восстановления. База автоматически не затирается. `restore-panel` проверяет суммы копии, сохраняет текущую БД и восстанавливает выбранный dump одной транзакцией. Автоматическое восстановление рассчитано на выделенную базу панели с пользовательской схемой `public`; дополнительные пользовательские схемы требуют ручного восстановления. Схема заменяется внутри транзакции, поэтому старые и переименованные таблицы не конфликтуют. Храните каталог установки и образы предыдущего выпуска до завершения проверки обновления. Копии содержат секреты; права каталога — 700, файлов — 600.

`backup-panel` сохраняет фактическое состояние процессов. При восстановлении ранее выключенные worker/scheduler остаются выключенными; копия полностью остановленной панели не запускает её автоматически. Для старых копий без списка процессов используется прежний режим запуска всех приложений. Контрольные суммы больших dump вычисляются потоком, без загрузки всей базы в память; конфигурация и файлы окружения также проверяются перед восстановлением.

## Перенос Marzban

Сначала установите Remnacust, подготовьте профили/хосты/ноды и внутренний сквад. Создайте API token с правами чтения пользователей и сквадов, создания пользователей. Это обычная авторизация API; установке она не нужна. У Marzban используйте администратора, который видит всех нужных пользователей.

```bash
sudo bash installer.sh migrate-marzban-panel \
  --source-url https://marzban.example.com \
  --destination-url https://panel.example.com \
  --internal-squad aaaaaaaa-aaaa-4aaa-aaaa-aaaaaaaaaaaa \
  --dry-run
```

Пароль Marzban и API token вводятся скрыто; для автоматизации доступны `MARZBAN_USERNAME`, `MARZBAN_PASSWORD`, `REMNACUST_API_TOKEN`. Удалённые API требуют HTTPS. HTTP допускается только на localhost, например через SSH-туннель. Redirect отклоняется, чтобы ключ не попал на другой адрес.

Команда сохраняет полный экспорт, план и отчёт в закрытом каталоге `/opt/remnacust/backups/marzban-*`. `--dry-run` не создаёт пользователей. После проверки отчёта повторите команду без этого флага. При конфликтах предварительная проверка останавливает весь импорт. Совпадающие записи пропускаются; отличающиеся не перезаписываются. После каждого создания проверяются ключи и назначение сквада. Частичный сбой возвращает ненулевой код и оставляет отчёт для повторного запуска. На время окончательного переноса остановите редактирование пользователей и обновление их квот в Marzban: API не предоставляет транзакционный снимок всей базы. Исходная панель и её пользователи этой командой не изменяются.

Переносятся VLESS UUID, Trojan/SS-пароли, сроки, дата создания, заметка и статус. Имена и пароли, не проходящие валидацию новой панели, не переименовываются и не генерируются заново. VMess и другие неподдержанные этим импортом протоколы требуют отдельной подготовки. `on_hold` становится `DISABLED`: срок активации по первому подключению автоматически не переносится. Бессрочный срок задаётся до 31.12.2099, годовой сброс — `NO_RESET`.

Счётчик потраченного трафика не поддерживается API создания пользователя. По умолчанию `--quota-mode remaining` переносит остаток квоты с `NO_RESET`; будущие продления настройте отдельно. Исчерпанная квота остаётся заблокированной. `--quota-mode total` сохраняет полную квоту и период сброса, но счётчик начинает с нуля, поэтому может повторно выдать уже потраченный трафик. Оба режима сохраняют исходные значения в экспорте.

`--preserve-subhash` сохраняет совместимый короткий токен. JWT-ссылки Marzban требуют отдельной subscription-page: `MARZBAN_LEGACY_LINK_ENABLED`, исходного `MARZBAN_LEGACY_SECRET_KEY`, API token и старого префикса. Смена DNS/proxy и установка legacy-page не выполняются этой командой. Проверьте старую ссылку и реальное подключение перед отключением Marzban. Администраторы, серверные конфиги, inbound-привязки и история трафика этой командой не импортируются.

## Исходные материалы и проверка

Схема панели/ноды сверена с [официальной установкой](https://docs.rw/install/remnawave-panel/) и [документацией ноды](https://docs.rw/install/remnawave-node/). Перенос Marzban использует те же документированные API и поля, что [официальный мигратор](https://github.com/remnawave/migrate) и [руководство по переносу](https://docs.rw/migrate/marzban/); реализация здесь своя.

Для TLS/XHTTP учитывался сценарий [mr-Abdrahimov/remna-node-xhttp](https://github.com/mr-Abdrahimov/remna-node-xhttp/blob/main/install_node.sh). Его полный скрипт не включён: здесь отдельная реализация без смены SSH, загрузки посторонних шаблонов сайта и общего `/dev/shm` для разных установок.

```bash
bash -n installer/installer.sh
bash installer/tests/bootstrap.sh
bash installer/tests/service-state.sh
PYTHONDONTWRITEBYTECODE=1 python3 installer/tests/test_installer.py
bash installer/tests/proxy-config.sh
# На выделенном Docker-стенде; создаёт и удаляет только собственный проект:
PYTHONDONTWRITEBYTECODE=1 bash installer/tests/panel-fresh.sh "$PWD" YOUR_PANEL_IMAGE
PYTHONDONTWRITEBYTECODE=1 bash installer/tests/node-integration.sh "$PWD" YOUR_NODE_IMAGE
PYTHONDONTWRITEBYTECODE=1 bash installer/tests/integration.sh "$PWD" YOUR_PANEL_IMAGE
```

## Удаление и возврат

`sudo remnacust uninstall-panel` и `sudo remnacust uninstall-node` требуют подтверждения. Удаляются только зарегистрированные контейнеры компонента; тома, `.env`, сертификаты и резервные копии сохраняются. На перенесённой установке сторонние сервисы не удаляются. Меню после удаления предлагает восстановить сохранённую установку. Для этого также можно выполнить `sudo remnacust start --component panel` или `--component node`. Полное удаление данных вручную выполняйте только после проверки резервной копии.
