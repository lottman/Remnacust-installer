# 1.2.73

Панель и страница подписки 1.1.7.42, Node 1.1.16, Core/WASM 1.1.11.

В настройках хоста и тега рядом расположены общий лимит скорости пользователя и отдельный предел приватного ключа устройства. Наследование из тега включается независимо для каждого ограничения. Значения задаются в Mbps; 0 отключает собственный предел. Существующие ключи не пересоздаются.

Общий бюджет пользователя динамически делится между его активными ключами: простаивающее устройство не резервирует скорость, а несколько соединений одного ключа не увеличивают его долю. При ограничении общей скорости хоста или тега сначала делится бюджет между пользователями, затем между их ключами. Это верхние пределы, а не гарантированная пропускная способность сети. Копии одного ключа считаются одним устройством. Для разделения физических устройств нужны отдельные ключи подписки. Между нодами сохраняется консервативное распределение, без переноса свободного бюджета между серверами.

Агент проверяет поддержку `remnacust-device-speed-v1` именно активным бинарником до применения положительного лимита устройства. Если новый предел выключен, неизвестное поле не передаётся старому агенту. Для новой функции обновите весь комплект. Добавлена миграция полей хостов и тегов; существующие лимиты пользователя сохраняются.

Основа ядра — официальный опубликованный Xray v26.10.21, без изменений из main после тега. Авторы отозвали прежние v26.10.10 и v26.10.17 из-за проблемных CA; обновлены корневые сертификаты и Go 1.27.3. Редактор, схемы и исходный архив ноды собираются из этого же ядра. Обновлены документация, четыре перевода интерфейса и зависимость follow-redirects 1.16.1.

Обновление: `sudo remnacust upgrade-panel --version 1.2.73`, затем на нодах `sudo remnacust upgrade-node --version 1.2.73`. Выбор NET_ADMIN сохраняет фактическое состояние существующего контейнера. Установка скачивает готовые образы; сборки на сервере нет.

[Официальный выпуск Xray](https://github.com/XTLS/Xray-core/releases/tag/v26.10.21).

XDRIVE в официальном v26.10.21 требует VLESS encryption/decryption и Mux на клиенте; старые нешифрованные XDRIVE-профили отклоняются валидатором. Перед обновлением такого профиля настройте согласованные ключи и совместимый клиент. Для остальных транспортов это новое требование не вводится.
