# Выпуск Remnacust

Исходники разделены между `Remnacust-panel`, `Remnacust-node`, `Remnacust-core` и `Remnacust-installer` в аккаунте lottman. Репозитории не удаляются при выпуске; новые изменения добавляются обычными коммитами.

1. Выполните проверки изменённых компонентов. Версии панели, ноды и ядра меняйте при изменении самих компонентов; для исправления только установщика общий новый тег не нужен. Архив ядра в ноде должен соответствовать исходникам выбранного ядра.
2. В `component-sources.json` установщика укажите репозиторий, полный хеш коммита и `version` каждого компонента. Обновите собственный `VERSION`, инструкции и тесты установщика, затем создайте новый тег. Установщик `v1.2.31` содержит панель `1.1.7.10`, ноду `1.1.6` и ядро `1.1.4`.
3. Запустите workflow `Publish Docker release` с этим тегом. Сначала проверяются установщик и закреплённые исходники, затем панель, нода и страница подписки собираются на отдельных amd64/arm64 runner. Нативные сборки исключают необходимость QEMU на пользовательском сервере. Каждый образ проверяется и публикуется в GHCR; копия `docker save` входит в Release.
4. Workflow проверяет digest, идентификатор, версию и архитектуру каждого образа, создаёт небольшой архив `remnacust-runtime-v1.2.31.tar.gz`, полный архив исходников и общий `SHA256SUMS`, затем загружает все файлы в черновик. Один раз переведите новые пакеты GHCR в Public через Package settings. Перед публикацией Latest проверьте анонимный `docker pull` и запуск образов на отдельном Docker-стенде. Предыдущие теги и файлы не заменяются.
5. Опубликуйте проверенный черновик и выполните `bash installer.sh --check-release --version latest`. Проверьте новую установку, обновление с сохранением прокси и удаление с сохранением томов. Для следующих исправлений используйте новый тег.

Пользователь скачивает готовый образ из GHCR по digest, без токена. При недоступности реестра установщик скачивает и проверяет тот же образ из Release. На VPS не устанавливаются инструменты сборки. Workflow использует временный `GITHUB_TOKEN` с `packages: write` для образов и `contents: write` для файлов выпуска. Запуск из PR не публикует образы. Старый workflow публикации исходников оставлен только для исторических тегов.

Для локальной проверки пакетировщика без загрузки других репозиториев задайте `--local-sources /path/to/parent`, где находятся три соседних checkout с нужными коммитами. Полученный архив имеет тот же состав и контрольную сумму.
