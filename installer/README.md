# Установщик Remnacust

## Обновление из панели

Журнал в панели автоматически прокручивается к новым событиям. Прокрутка вверх приостанавливает слежение до возврата вниз; новый запуск обновления снова включает его.

Основные файлы новой установки: `panel/docker-compose.yml`, `panel/.env`, `node/docker-compose.yml`, `node/.env` внутри `/opt/remnacust`. Фактические пути существующих установок смотрите в `/opt/remnacust/FILES.txt` и в `FILES.txt` каталога компонента. Миграция может сохранять прежний рабочий каталог и тома. Секреты в карту файлов не попадают.

Старые `compose.remnacust-<дата>-<номер>.json` и `Caddyfile.before-first-vpn` после обновления убираются из рабочих каталогов в `/opt/remnacust/backups/<компонент>/legacy-config-<идентификатор>/`. Там сохраняются исходные файлы и `manifest.json` с путями, правами и SHA-256. Обычные копии обновления и отката также остаются внутри `backups/`. `.env`, действующий Compose, сертификаты и данные не удаляются. Файлы, на которые ссылаются реестр, Compose любого профиля, Caddy/Nginx или контейнеры, включая остановленные, остаются на месте. Пользовательские файлы с другими именами не трогаются.

Для упорядочивания накопившихся копий без обновления и перезапуска сервисов выполните новым установщиком:

```bash
sudo bash installer.sh cleanup-backups
# Или только выбранный компонент:
sudo bash installer.sh cleanup-backups --component node
```

Команда обрабатывает зарегистрированные панель, ноду и страницы подписки. Повторный запуск не создаёт дубликатов. При недоступном Docker или ошибке разбора Compose файлы не перемещаются. Старые резервные каталоги не удаляются по возрасту: они могут понадобиться для отката. Не удаляйте `compose.remnacust-*` вручную через маску — прежний контейнер ещё может использовать один из них. Для нестандартной установки каталог резервных копий должен находиться на той же файловой системе, что и конфиги; иначе исходники остаются на месте.

Новый установщик настраивает `remnacust-panel-update.service` при установке или обновлении панели. На прежней установке один раз выполните `upgrade-panel` через новый скрипт. Требуется systemd; без него используйте команду `remnacust`.

Администратор может запустить обновление из окна версии панели, когда доступен новый выпуск. Сервис продолжает работу после остановки backend или закрытия вкладки. Он проверяет выпуск установщика и соответствие версии панели, затем выполняет `upgrade-panel --yes`: резервная копия, обновление приложений и проверка готовности. Повторный запрос не создаёт вторую операцию. Ноды и существующий reverse proxy не перезапускаются. Браузеры перезагружаются после завершения; при ошибке показывают результат и позволяют вернуться в панель.

Приложения получают только каталог управления `/run/remnacust-control` через bind mount с запретом записи. Docker socket в контейнер не передаётся. Локальный Unix socket защищён правами `0600` и ключом, производным от исходного `APP_SECRET`; API-токены панели не могут запускать обновление. Журнал: `logs/panel-update-<идентификатор>.log` в каталоге установщика, доступ только для root.

## Установка

Мастер панели предлагает установить страницу подписки (`y/n`, по умолчанию `n`). При согласии нужен отдельный домен сайта; можно указать два домена. Без сайта используются ссылки панели `/api/sub`. Для установки без диалога: `--subscription-page --subscription-urls sub.example.com --yes` или `--no-subscription-page --yes`. Режим `--yes` не запрашивает необязательный сайт; согласие задайте флагом явно. Для уже работающего сайта задайте `--no-subscription-page --subscription-urls https://sub.example.com`: контейнер сайта не создаётся. Занятый порт страницы можно заменить, порты панели и HTTPS исключены.

Повторная установка отдельной страницы на той же панели сохраняет идентичность действующего служебного API-токена, вместо создания дубликатов. Подпись, срок, наличие токена в БД и минимальные права проверяются внутри панели. Отозванная идентичность не восстанавливается. В токене сайта нет управления пользователями; совместимость старых username-ссылок Marzban требует отдельного `users:by-username` только если эта функция включена.

`installer.sh` устанавливает, обновляет и обслуживает панель и ноду. Требуются Ubuntu 22.04, 24.04 или 26.04 LTS и root-доступ. Сервер скачивает готовые Docker-образы; сборка на сервере не нужна.

Меню пронумеровано сверху вниз: 1–3 — установка панели, ноды и страницы подписки; 4–6 — их обновление; 7–9 — перенос; 10–13 — обслуживание; 14–15 — удаление панели и ноды. 0 — выход. В пункте 12 выберите панель, ноду или страницу подписки: доступны состояние, адреса и пути настроек, журнал, запуск, остановка, перезапуск и смена домена. Для установленного компонента рядом с пунктом установки показаны номера обновления и удаления.

**Подтверждение адресов и повторная установка.**

После ввода домена панели, ноды или отдельной страницы скрипт повторно показывает его и спрашивает `Использовать домен …? y/n [y]`. Enter подтверждает адрес; `n` возвращает к вводу. То же подтверждение есть у списка доменов встроенной страницы и при смене домена. Остальные вопросы сохраняют прежний ответ `n` по умолчанию. В автоматизации явные параметры без терминала и `--yes` не требуют дополнительного ввода.

Повторный выбор установки отдельной страницы распознаёт зарегистрированный каталог или проект и открывает управление существующей страницей до скачивания образов и проверки порта. Вторая копия и новый токен не создаются. Для действительно отдельного сайта укажите другой проект, каталог и свободный порт. При установке без явного проекта и каталога занятый порт дополнительно проверяется по Docker Compose: зарегистрированная наша страница обновляется на месте. Потерянная запись реестра восстанавливается только для образа ghcr.io/lottman/remnacust-subscription-page внутри текущего корня установки. Compose пересоздаёт только сервис страницы, сохраняя порт, .env, токен и остальные контейнеры. Имя процесса или номер порта сами по себе не доказывают принадлежность. Домен существующей страницы сохраняется; для смены используйте управление страницей. Если выбранный порт занят другой установкой или сервисом, интерактивный запуск предлагает ввести другой свободный порт; существующий контейнер не останавливается и порт принудительно не освобождается. Без терминала и с `--yes` конфликт завершает действие: укажите свободный `--port` явно. Успешная установка или обновление страницы завершает меню, чтобы случайное повторение не приводило к сообщению о занятом порте.

**Страница подписки и панель обновляются отдельно.** Установка сайта не обновляет интерфейс панели. Скрипт выводит фактическую версию установленной страницы. Если выбран внешний reverse proxy, установка не перенаправляет существующий публичный домен и не заменяет `SUB_PUBLIC_DOMAIN` панели: настройте маршрут HTTPS к указанному loopback-порту, затем задайте публичный адрес в фактическом окружении панели. Смотрите `FILES.txt`: отдельный `.env` может отсутствовать, а явный `environment` в Compose имеет приоритет над `env_file`. Пересоздайте приложения после изменения окружения. Само появление контейнера в разделе управления страницами не меняет ссылки, выдаваемые пользователям.

Чтобы скачать скрипт и открыть меню:

```bash
curl -fsSL --proto '=https' --proto-redir '=https' https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh -o installer.sh && sudo bash installer.sh
```

Команду можно передать сразу:

```bash
sudo bash installer.sh install-panel
sudo bash installer.sh install-node --port 2222
sudo bash installer.sh upgrade-panel
sudo bash installer.sh upgrade-node
sudo bash installer.sh --help
```

API-порт новой ноды по умолчанию — `2222`. Укажите его вместе с адресом сервера в разделе «Ноды» панели. Скрипт проверяет диапазон и занятость порта. Обновление и миграция сохраняют фактический порт прежнего контейнера; `--port` доступен только при новой установке. SSH-порт не меняется.

При установке новой панели скрипт спрашивает пароль резервных копий. Ввод скрыт; Enter создаёт пароль автоматически. После успешной установки пароль показан в итоговой памятке и сохранён в `backup-password.txt` в каталоге панели с правами `0600`. Он нужен для открытия раздела «Резервные копии» и расшифровки архивов. При запуске без терминала можно передать его через `REMNACUST_BACKUP_PASSWORD`; без этой переменной пароль создаётся автоматически. Обновление и миграция сохраняют прежние пароль и ключ.

При новой установке панели выберите «Установить сайт подписки? y/n». При `y` задайте один или два отдельных домена через запятую; при `n` остаются подписки через панель. Для автоматизации: `--subscription-page --subscription-urls 'sub.example.com,other.example.com'`. Для готового внешнего сайта: `--no-subscription-page --subscription-urls 'https://sub.example.com/sub'`. При собственном proxy сайт доступен на loopback-порту `3010`. Подробности — в [основном README](../README.md#адреса-сайта-подписки).

`runtime.py` готовит Compose и проверяет состояние контейнеров. `database.cjs` проверяет совместимость БД и переносит её без изменения секретов. `subscription.cjs` выдаёт сайту подписки ограниченный токен. `marzban.py` готовит и выполняет перенос пользователей Marzban. `tests/` содержит проверки установщика.

Скрипт выпуска содержит помощники своей версии и проверяет их перед использованием. Старые установленные файлы или выбор старой версии приложения не меняют этот комплект. Сервис обновлений также закреплён за своим комплектом. [Работа без сети, кеш и подготовка выпуска](../docs/INSTALLER-HELPERS.md).

Все команды, сертификаты, резервные копии, миграция и удаление описаны в [основном README](../README.md).

После успешного обновления автоматически очищаются старые образы Remnacust. Текущий, предыдущий и используемые контейнерами образы сохраняются. [Подробности](../docs/IMAGE-CLEANUP.md).


## Управление установленными компонентами

Страницу подписки можно удалить отдельно: пункт **16** главного меню, пункт **8** в управлении страницей или `remnacust uninstall-subscription-page --page-id ID`. Без ID открывается выбор страницы с её доменом и состоянием; подтверждение по умолчанию — `n`. Команда удаляет только выбранные контейнеры страницы и принадлежащего ей отдельного proxy, сохраняя настройки, сертификаты и тома. Общий proxy панели и сама панель продолжают работать. Исходная конфигурация сохраняется в `backups/uninstalled-subscription-page-*/`; обычный запуск Compose не восстанавливает удалённую страницу. При повторной установке её старые файлы переносятся в `backups/reinstalled-subscription-page-*/configuration`.

```bash
sudo remnacust manage-panel
sudo remnacust manage-node
sudo remnacust manage-subscription-page
sudo remnacust show-config --component panel
sudo remnacust restart --component node
sudo remnacust status --component subscription-page --page-id ID
sudo remnacust logs --component subscription-page --page-id ID
sudo remnacust change-domain --component panel --domain panel.example.com
sudo remnacust change-domain --component node --domain node.example.com --email admin@example.com
sudo remnacust change-domain --component subscription-page --page-id ID --domain sub.example.com
```

Смена адреса означает смену домена компонента, без переноса сервера и изменения его IP. Домен вводится без протокола, порта и пути. Заранее настройте A/AAAA; для HTTP-01 и автоматического Caddy установщик проверяет их соответствие IP сервера (`--server-ip` учитывает NAT). Способ TLS сохраняется: автоматический Caddy сам получает сертификат; для Certbot используется прежний HTTP/DNS-метод, при необходимости запрашиваются email или INI DNS-провайдера. Для готового сертификата нужно указать новую пару `--cert-file` / `--key-file`, покрывающую новый домен. Существующие SAN сайта подписки сохраняются. Произвольный внешний Nginx, CDN и конфигурации proxy, которые установщик не создавал, автоматически не переписываются: для них смена останавливается до применения настроек.

В панели обновляются `FRONT_END_DOMAIN`, `PANEL_DOMAIN` и связанный адрес подписки; независимый домен сайта подписки остаётся прежним. Локальные зарегистрированные страницы, обращающиеся к панели по старому публичному URL, получают новый адрес backend. Встроенная страница меняется отдельно, включая адрес в настройках панели и общий Caddy. На ноде обновляются управляемый Nginx и сертификат; если управляемого TLS ещё нет, добавляется Nginx с прежним API-портом и ключом ноды. Адрес/SNI в хостах панели и ранее выданных клиентских подписках нужно обновить отдельно.

До изменений создаётся закрытая копия в `backups/domain-<компонент>-<идентификатор>/`. Проверяются Compose и конфигурация proxy. Для работающего Caddy дополнительно проверяется HTTPS нового домена, до двух минут; панель должна вернуть свой ответ `/api/auth/status`. Образы, ключи, пароли, БД, тома и API-порты не меняются. Пересоздаются только приложения и управляемый proxy; остановленные сервисы остаются остановленными. При ошибке восстанавливаются исходные файлы, сертификаты, реестр, карта `FILES.txt` и состояние запуска. Прерванный план можно откатить вручную проверенным помощником `management.py rollback --root /opt/remnacust --plan /путь/к/plan.json`; путь актуального комплекта указан в установленном скрипте. Копии содержат секреты: не публикуйте их.

При смене домена через Certbot активный UFW временно отключается и включается обратно после успеха, ошибки или обычного прерывания. Если UFW был выключен или не установлен, его состояние не меняется. Перед отключением ставится независимый таймер восстановления через 10 минут и загрузочная задача `remnacust-ufw-restore.service`; они защищают также от принудительного завершения процесса и перезагрузки сервера. При ошибке повторного включения задача сохраняется, операция завершается ошибкой. Состояние восстановления хранится в `/var/lib/remnacust-ufw-recovery/required`; правила UFW не сбрасываются. Дополнительные ограничения nftables ноды и firewall провайдера продолжают действовать. HTTP-01 требует входящего TCP 80; при настроенном ограничении ноды он открывается временно её отдельным ACME-правилом.

Автопродление Certbot использует ту же защиту UFW и сохранённый способ ACME. Автоматический TLS Caddy не требует отключения UFW. Журнал операций находится в `/opt/remnacust/logs`, резервная копия и путь плана выводятся перед изменениями.

## Восстановление данных (готовится к выпуску)

`restore-panel` сохраняет установленную версию и инфраструктуру, возвращая БД и `APP_SECRET` выбранной копии. Старые PostgreSQL/Redis/Compose из архива автоматически не запускаются. Встроенный сайт подписки получает токен для восстановленного ключа, локальный сервис обновления — соответствующий производный ключ. Остановленные приложения остаются остановленными; при сбое миграции сохранены ключ и метаданные восстановленной БД. Явные значения ключей и токена записываются в приватный Compose; текущие env-файлы сохраняются. Порядок, ограничения и приоритет переменных описаны в [основном README](../README.md).
