# 1.2.82

Панель и страница подписки 1.1.7.48. Нода 1.1.18 и Core/WASM 1.1.11 остаются прежними. Миграция добавляет необязательные поля черновика к шаблонам и истории, сохраняя существующие данные. Сборка 1.2.81 остановлена до публикации: все её исправления включены сюда.

- Кнопка сохранения доступна при ошибках в GUI и редакторе кода. Общий серверный обработчик сохраняет некорректный JSON/YAML и незавершённые настройки как черновик с предупреждением и историей. После перезагрузки текст восстанавливается; подписка использует последнюю рабочую конфигурацию. Исправленный шаблон применяется при следующем сохранении. Ошибка записи БД не считается успешным сохранением.
- Числовой `leastLoad.tolerance` вне диапазона 0–1 применяется с предупреждением: Xray ограничивает значение до этого диапазона. Исходное число сохраняется; `2` не означает две ноды. `expected` задаёт количество кандидатов.
- Новый автовыбор сразу получает подходящие включённые хосты по UUID вместо пустого обязательного селектора. Пулы и связанные балансеры объединены в общую карточку. Удаление связанной группы сохраняет независимые правила и ручные outbounds.
- В geofiles добавлен переключатель «Загружать клиенту». В новой привязке он выключен: категории направляются в DIRECT, правила встроены в полную подписку. При включении приложение получает удалённый набор и использует выбранное действие. Старые привязки без нового поля сохраняют прежнее поведение.
- DAT для удалённой загрузки преобразуется в JSON rule set sing-box или YAML classical provider Mihomo/Clash/Stash. Производные ссылки подписаны и не раскрывают адрес источника. Изменённая подпись отвергается. Нативные JSON/YAML/text могут встраиваться без URL. SRS остаётся удалённым бинарным набором; для встраивания нужен исходный JSON.
- Клиентский интервал обновления — от 5 минут до 30 дней, по умолчанию сутки. Он передаётся в `update_interval` / `interval`; приложение выполняет первую загрузку, кеширование и своё расписание. Ручное обновление клиента может обходить этот интервал.
- В общей библиотеке настраиваются HTTPS-источник, автозагрузка на сервер и отдельный интервал от 15 минут до 30 дней. Импорт по URL запоминает источник, автозагрузка по умолчанию выключена. Для файла с ПК можно назначить источник. Планировщик проверяет расписание раз в минуту; перезапуск, ошибки и ручные повторы не сбрасывают интервал. Параллельная загрузка одного файла предотвращается между процессами.
- Сервер повторно проверяет адреса и перенаправления против SSRF, размер, формат и категории действующих шаблонов. Ошибка сохраняет последнюю исправную версию. Исходные URL с хешем остаются неизменными; `latest` и подписанные ссылки отдают актуальные данные без immutable-кеша. Кеш компиляции учитывает хеш активного файла.
- Массовые действия с хостами отвечают после записи БД, не ожидая обхода всех нод. Политики доставляются в фоне с повторами. Интерфейс показывает выполнение и обновляет список после подтверждения API. Клонирование ограничено тремя параллельными запросами; неудачные источники остаются выбранными для повтора.
- Поиск флагов принимает названия стран на RU/EN/FA/ZH и двухбуквенный код независимо от языка интерфейса.
- X25519 показывает приватный ключ и «Пароль (публичный ключ)». Дублирующее поле убрано; копирование всех значений содержит только `password` и `privateKey`.
- Обновлены контракты, OpenAPI, документация и сообщения на четырёх языках, проверены мобильная раскладка, RTL и темы.

Обновление панели: `sudo remnacust upgrade-panel --version 1.2.82`. Нода для этих исправлений не обновляется. После изменения клиентских параметров обновите полную JSON/YAML-подписку: отдельная ссылка VLESS не передаёт маршрутизацию.

Xray JSON получает встроенные правила. Его geodata downloader обновляет уже существующие файлы и не гарантирует первичную установку произвольного DAT во всех приложениях. GUI поясняет это ограничение; неподдерживаемая настройка из кода сохраняется как черновик с предупреждением. Совместимость конкретных физических клиентов не заявляется как универсальная.
