# Сайт selfsteal на ноде

[Русский](NODE-SELFSTEAL.md) · [English](NODE-SELFSTEAL.en.md)

При установке ноды с собственным доменом установщик автоматически выбирает случайный сайт из локального каталога. В каталоге не менее 20 вариантов на разные темы: от обуви и кофе до Minecraft-хостинга. Все страницы, стили, скрипты и графика поставляются вместе с установщиком; внешние CDN для их работы не нужны.

Выбор выполняется один раз. Перезапуск, обновление ноды и продление сертификата не выбирают новый вариант. Если вы изменили содержимое сайта, установщик сохраняет ваши файлы.

## Установка

Запустите `install-node` с параметром `--node-domain` либо укажите домен в интерактивной установке. Подтвердите домен и выберите способ получения сертификата. Отдельного вопроса о теме сайта нет: вариант выбирается автоматически.

Для selfsteal домен должен вести на IP ноды и работать в DNS-only, без CDN с завершением TLS. Профиль Xray принимает HTTPS на внешнем порту и направляет обычные обращения на локальный TLS-сайт Nginx. В штатной схеме установщика Nginx использует сокет `/var/lib/remnacust/run/nginx.sock` и PROXY protocol; параметры `target` и `xver` профиля должны соответствовать этой схеме. Сами файлы сайта не создают и не изменяют inbound в панели. Пока подходящий профиль Xray не запущен, наличие файлов не означает, что публичный HTTPS уже доступен.

### Отдельный HTTPS-сайт и каскад

При установке и переносе можно выбрать «Отдельный HTTPS-сайт». Скрипт спрашивает порт сайта (по умолчанию 443) и порт входа Xray в профиле панели (по умолчанию 8443). Порт API ноды задаётся отдельно и при переносе сохраняется. Все три порта должны отличаться. Для HTTP-01 порт 80 резервируется под выпуск и продление сертификата; для других вариантов используйте DNS-01 или готовый сертификат.

В этом режиме Nginx самостоятельно принимает HTTPS на порту сайта: страница работает без активного профиля Xray. Локальный сокет остаётся доступен. Установщик разрешает только TCP-порт сайта в своём ограничении по IP и создаёт отдельный профиль UFW; SSH и другие правила не изменяются. Изначально выключенный UFW не включается. Внешний firewall провайдера должен разрешать выбранный порт. При смене порта обновляется только собственный профиль UFW; при удалении ноды или переходе на selfsteal исключение сайта снимается.

При включённом UFW TCP-порты API и выбранного входа Xray разрешаются отдельным управляемым правилом только от IP/CIDR главного сервера. Общего разрешения этих портов нет. Удаление ноды снимает собственное правило этой установки и удаляет её контейнер `node-nginx`; чужие прокси, файлы сайта, сертификаты и резервные копии сохраняются. Собственный таймер продления сертификата отключается.

Перед завершением установки проверяется настоящий локальный HTTPS-ответ с именем домена и установленным сертификатом. При смене режима ошибка этой проверки запускает откат настройки сайта.

Для схемы «сайт 443, REALITY 8443» задайте в профиле панели вход на 8443 и REALITY `target: "127.0.0.1:443"`, `xver: 0`, `serverNames: ["node.example.com"]`. Внешнему TCP-слушателю Nginx PROXY protocol не нужен. `acceptProxyProtocol: true` во входе Xray включайте только если главный сервер отправляет этот протокол. Для локального сокета Nginx требуется `xver: 1`.

Выбранный порт Xray сохраняется в настройках установки и показывается в итоговой инструкции. Скрипт не переписывает действующий профиль в панели: выставьте в нём этот порт и соответствующий REALITY target. Настройка `--port` относится к API ноды.

Для автоматизации доступны `--node-site-mode standalone`, `--node-site-port 443`, `--node-inbound-port 8443`; режим `--node-site-mode selfsteal` сохраняет прежнюю схему с локальным сокетом. Обновление ноды сохраняет выбранный режим и порты. Чтобы изменить режим уже установленной ноды, используйте `change-domain --component node` с этими параметрами; домен может оставаться прежним.

## Файлы и правки

Nginx работает в Docker как `node-nginx`; службы `nginx.service` на хосте нет. Проверить его состояние и журнал:

```bash
cd /opt/remnacust/node
docker compose ps
docker compose logs --tail=80 node-nginx
```

В режиме selfsteal ограничение по IP главного сервера закрывает прямой доступ внешним посетителям и CDN. В режиме отдельного сайта исключением является только его TCP-порт. Работающий контейнер Nginx сам по себе не отменяет другие ограничения firewall.

При стандартном размещении файлы находятся в `/opt/remnacust/node/www/`. Изменяйте HTML, CSS, JavaScript и графику в этом каталоге. Сайт статический: каталог товаров, подборки, фильтры и калькуляторы работают в браузере. Для реальных заказов, оплаты или создания игровых серверов нужно отдельно подключить собственную службу и контакты; таких действий сайт сам не выполняет.

Не размещайте в `www` `.env`, ключи, дампы или резервные копии. Каталог доступен посетителям. Настройки выбранного варианта хранятся отдельно от публичных файлов.

## Другой случайный сайт

В актуальном установщике откройте «Управление → Нода → Выбрать другой случайный сайт» либо выполните:

```bash
sudo remnacust configure-node-site
```

После подтверждения текущие файлы сохранятся в `/opt/remnacust/backups/node-sites/`, затем будет выбран другой вариант. Работающий Nginx пересоздаётся для подключения нового каталога; остановленный сайт не запускается. Процесс Xray и его профиль это действие не изменяет. Если Nginx не удастся запустить, установщик попробует восстановить прежний сайт и покажет результат в журнале.

Команда доступна в версии установщика с каталогом сайтов. Если установленный CLI её ещё не знает, сначала скачайте актуальный `installer.sh` из Latest и запустите команду через него.

## Исходники вариантов

Все варианты находятся в `sites/` этого репозитория. `scripts/build-node-sites.py` собирает проверенный каталог для установщика. При добавлении собственного варианта нужны как минимум главная страница, страница о сайте и страница 404; все локальные ссылки и ресурсы должны существовать. Сборка и проверки каталога выполняются перед публикацией.
